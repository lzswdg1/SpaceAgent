## 必须优先修正

### P1：组织列表查询失败却同时显示零记录

数据库有 10 个活跃组织，总览正确显示 10；组织管理页实际出现 `Platform administration data is unavailable`，同时显示 `0 RECORDS`、`No organizations`。对应业务后端日志记录 `org.springframework.jdbc.BadSqlGrammarException`。

这不是组织不存在，而是列表查询失败。需要修复组织查询，并将失败、加载中、空列表区分为独立展示状态；失败时不能把初始 `total=0` 当成有效统计。定位：`OrganizationsPage.tsx:36-46,126-132`；`PostgresIdentitySystemAdministrationQuery.java:133-163`（查询拼接）。本次只确认实际错误类型，未修改或执行修复。

### P1：UNKNOWN 风险漏报

数据库中 `platform_model_call_ledger.status='UNKNOWN'` 有 **4** 条，工具 UNKNOWN 为 0；页面仍显示 UNKNOWN 影响为 0。

- `apps/platform-server/src/main/java/com/spaceagent/platform/runtime/infrastructure/persistence/PostgresRuntimeSystemAdministrationQuery.java:22` 把 `unknown_runs` 写成常量 `0::BIGINT`。
- `apps/admin-web/src/pages/OverviewPage.tsx:48` 仅相加 runtime/tooling 的值，没有模型调用。

应明确分别统计“结果不确定的模型调用/工具执行/运行”，不要把不同实体混成一个无法解释的数字，更不能用常量 0 表示已排查。

### P1：在线人数、执行中状态的口径不可信

- `OverviewPage.tsx:44` 把 `identity.recentlyActiveUsers` 标为“当前在线人数”；它实际是最近 5 分钟访问活动，不是在线心跳。
- Sessions=19 实际是未过期、未撤销的刷新令牌数量，不是在线人数，也不是 19 个物理设备。
- 执行中=2 来自 Run 状态筛选；两条 IN_PROGRESS 的 `updated_at` 都停留在 **2026-08-23**。这不证明当前仍在执行，应检查运行恢复/租约并区分滞留状态；本次未终止或修复运行。
- 新 Admin `/admin/v1/presence` 实际返回 **503 / ADMIN_PLATFORM_UNAVAILABLE**。业务服务仍为 V1084，U01 的 V1085 Presence 接口尚未部署；前端也未对接该接口。不可声称真实在线功能已运行。

### P1：健康/安全标识被写死

- `OverviewPage.tsx:51` 的 ADMIN WEB → ADMIN SERVER → mTLS/JWT → PLATFORM 是固定结构和样式，不是实时探测到的部署拓扑。
- `OverviewPage.tsx:57` 的 `VERIFIED` 和风险列表 `LIVE` 是静态文字。
- `PlatformSystemAdministrationHttpController.java:99,109` 的 `UP` 是接口构造时写入的常量，不是逐项健康探测结论。
- 总览只在进入页面或切换时间范围时请求；没有实时推送或周期刷新。不能把一次成功读取长期标为实时。

应显示“更新时间/刷新失败/未检测/当前快照”，只有具备对应检查证据时才显示通过。

### P1：已删除业务仍留在前端

`apps/admin-web/src/adminApi.ts:144` 请求 `/admin/v1/agent-version-governance/evidence`，实际返回 **404**，总览底部实际显示 `Request failed (404)`。当前 Agent 已不采用旧版本治理模型。

应移除旧版本治理展示；若展示当前配置审批，只能接当前配置变更审核的真实接口，不能用假数据填补旧卡片。

## 语言与信息层级

### P2：不是缺几个翻译，而是组件绕过了翻译层

总览、外壳、资源页及多个表格将 `GLOBAL SYSTEM SCOPE`、`PROJECTION FRESHNESS`、`RISK QUEUE`、`ACTIVE`、`OPERATION` 等直接写入 JSX。

定位：`App.tsx:84-85`、`OverviewPage.tsx:39-57`、`ResourcesPage.tsx:10`、`UsersPage.tsx:178`、`CommandsPage.tsx:60-63`、`AuditPage.tsx:48-62`。这些内容不调用 `tx()`，因此中文/日文都会遗留英文；日文问题依据共享渲染代码确认，本次未修改用户语言偏好。

文案还存在面向开发者的说法，例如“权威投影”“耐久清理”“命令调和”。建议改为“数据更新时间”“删除进度”“操作记录/状态核查”等用户可理解的表述；技术状态码放详情和复制入口。

### P2：低价值内容占首屏，重复统计，没有决策层级

标题最高 76px，页头和架构说明占大块空间；静态拓扑、模块英文副标题、PRIVATE/ACTIVE/VERIFIED 徽章重复出现。总览与资源页又读取同一个 dashboard 接口并重复铺设计数，而不是资源检索/消耗明细。

推荐首屏仅保留关键指标和待处理异常；用户/组织/资源进入对应列表；资源页展示真实明细与用量。技术 ID、架构、安全机制和版本信息放折叠详情；危险操作确认、权限不足、未知结果警告不能因精简而删除。

审计页应说明目前是管理员行为审计，不能暗示已覆盖平台所有普通用户操作。CPU、内存、网络和存储消耗尚未由这一组页面/接口完整提供。
