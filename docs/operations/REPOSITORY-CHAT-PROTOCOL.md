# 仓库对话：正文伪工具调用的处理

更新：2026-09-15。

## 问题与修复

模型可能返回 `finish_reason=stop`，却把 `<invoke name="file_read">…` 等操作写进正文，
没有提供结构化 `tool_calls`。原流程将非空正文当作最终答案；Markdown 的安全 HTML 过滤
隐藏标签后，用户只看到“我继续读取代码”的开场白，而 Run 已被标成 COMPLETED。

仓库对话现在在发布正文前检测未包在代码示例中的协议形状（invoke/function_calls/tool_call）。
普通围栏、缩进代码和行内代码示例保留。只做异常识别，不解析其中的参数，更不执行文本标签。

- 每个仓库模型轮次最多增加一次纠正请求，要求模型用原工具 schema 的结构化调用，或输出真实答案。
- 纠正逻辑 ID 为原 `stepId:inference:round` 加 `:protocol-correction`，和原请求分别进入
  ModelCallLedger/预算结算。成功响应的 Token 总数包含两次实际请求，禁止无账本调用。
- 工具、沙箱、工作区范围、模型配置和预算仍沿用原授权；已经进入工具关闭的收尾轮次不会重新开放工具。
- 网络失败、Provider UNKNOWN、取消和预算拒绝直接沿原流程处理，不当作协议异常再重试。
- 第二次仍有伪工具正文时返回 `CHAT_TOOL_PROTOCOL_INVALID`，Run 失败而不是完成；已执行工具不重放。
- 异常正文不进入 SSE 最终答案或 Conversation。仓库轮次正文在响应校验后发布，推理/运行事件仍可传递。
  前端安全过滤保持开启；纠正过程仅发送不含正文的 `tool_protocol_correction` 事件。

这不是通用“回答质量保证”：没有协议标记但内容不充分的自然语言回复，不能仅靠该检测器判断完成度。
历史错误回答不自动删除或重跑，现有真实调用也不会在开发验证期间被重新执行。

## 验证与上线边界

38 项定向测试通过：伪调用恢复、重复异常失败、UNKNOWN 不重试、工具关闭限制、独立账本 ID、
Token 合计、SSE/历史一致性、XML 示例、原有续写/取消及租户工作区边界。架构和 diff 检查通过。
测试使用假模型；没有真实付费请求。本次仅验证源码，后端容器未重启，需部署新版后对新请求生效。
